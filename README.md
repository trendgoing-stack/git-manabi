# Gitまなび帳

Git・GitHub CLI（gh）・GitHub の操作を、「やりたいこと」と「コマンド名」の両方から引ける学習向けの辞典です。
「コミットを取り消したい」のような言葉でも、`reset` のようなコマンド名でも探せて、入力欄を埋めるだけで実行できる形のコマンドが作れます。

**▶ アプリを開く: https://trendgoing-stack.github.io/git-manabi/**

登録やログインは不要です。無料で使えます。

## できること

- **検索** — 「やりたいこと」（例：ブランチを消したい）でも、コマンド名（例：`git sw`）でも探せます。カタカナ・ひらがな・全角英字でも見つかります。ツール（git／gh／GitHub の画面）やカテゴリで絞り込めます。検索語が空のときは、カテゴリ一覧と「毎日の作業」「やり直したいとき」などのシーン別チートシートを表示します
- **コマンドビルダー** — ブランチ名やメッセージを入力欄に入れると、完成形のコマンドができます。よく使うオプションはボタンで ON／OFF でき、同時に使えないものは選べないようになっています。「コピー」でそのままターミナルに貼り付けられます
- **危険なコマンドの確認** — 変更が消えるなど「危険」なコマンドをコピーするときは、危険な理由と元に戻す方法を先に表示します
- **ブランチ図** — merge・rebase・reset などを実行する前と後で、ブランチやコミットがどう動くかを図で確認できます
- **困った** — 「コミットを取り消したい」「コンフリクトした」などの状況から、質問に答えていくと使うコマンドにたどり着けます
- **学ぶ**
  - **クイズ** — やりたいことからコマンドを、コマンドからやりたいことを4択で答えます。1セット10問。間違えた問題を集中して復習することもできます
  - **フラッシュカード** — 表にやりたいこと、裏にコマンド。左右にスワイプしてめくれます
  - **用語集** — 五十音順に並んだ用語を検索できます。説明文中の用語をタップしても意味を確認できます
- **マイ** — お気に入り、閲覧履歴、項目ごとの自分用メモ、自作のコマンド（スニペット）をまとめて見られます。スニペットも検索やコマンドビルダーで使えます

## iPhoneで使う

ホーム画面に追加すると、アプリのように全画面で使えます。一度開けば、電波のない場所でも起動します。

1. **Safari** で上のリンクを開く
2. 画面下の共有ボタン（□に↑のアイコン）をタップ
3. 「ホーム画面に追加」をタップ

> [!IMPORTANT]
> Safariで開いた場合とホーム画面から開いた場合では、お気に入りやメモが**別々に保存**されます。
> 普段使うときは、ホーム画面のアイコンから開くようにしてください。
> 移したいときは、設定の「エクスポート」で書き出し、もう一方で「インポート」できます。

AndroidやPCでも、ChromeやEdgeなどのブラウザで同じように使えます。

## アプリの更新

新しいバージョンや辞書の追加が用意できると、アプリを開いたときに画面の上部に
**「更新があります（タップで再読み込み）」** と表示されます。
タップすると最新版に切り替わります（お気に入りやメモはそのまま残ります）。表示されないときは、すでに最新版です。

いま使っているアプリと辞書データのバージョンは、設定画面のいちばん下で確認できます。

## データについて

- お気に入り・閲覧履歴・メモ・スニペット・クイズの成績・設定は**お使いの端末の中だけ**に保存されます。サーバーには送信されないので、ほかの人に見られることはありません
- そのため、**機種変更やブラウザのデータ削除をするとデータは消えます**。設定の「エクスポート」で定期的にバックアップを取っておくと安心です
- 設定の「すべてのデータを削除」で、このアプリのデータだけをまとめて消せます
- アクセス数の計測に [GoatCounter](https://www.goatcounter.com/) を使っています。送るのはアプリを開いたときの1回だけで、記録されるのは「開かれた回数」だけです。クッキーは使わず、検索した言葉や見た項目、メモの内容が送られることはありません。設定の「アクセス解析を送信しない」で止めることもできます

## ご利用にあたって

- 説明文はすべてオリジナルの要約です。正確な仕様は、各項目の「公式ドキュメント」から確認してください
- 危険なコマンドを実行する前は、バックアップを取るか、ブランチを作っておくと安心です
- GitHub の画面は変わることがあります。手順どおりの場所にボタンが見つからないときは、GitHub Docs を確認してください
- このアプリはコマンドを表示・コピーするだけで、実行はしません

## はじめて使うときは

検索タブのシーン別チートシート「はじめての準備」と「毎日の作業」から見ていくのがおすすめです。
困ったときは「困った」タブで今の状況を選ぶと、使うコマンドにたどり着けます。

## 開発者向け

ビルド不要の静的サイトです（バニラ JavaScript の ES Modules ＋ HTML ＋ CSS。外部ライブラリや CDN は使いません）。ファイル構成や開発用ツールは [DEVELOPMENT.md](DEVELOPMENT.md)、辞書データの書き方は [CONTENT.md](CONTENT.md)、実機確認のチェックリストは [TESTING.md](TESTING.md) にあります。

### 手元で動かす

```bash
python -m http.server 8765
```

http://localhost:8765/ を開きます（ファイルを直接開くと動きません）。

### 公開（GitHub Pages）

`main` ブランチの `/ (root)` を GitHub Pages で公開しています。`main` に push すると、数分で公開中のアプリに反映されます。

### 更新するとき

利用者の端末には Service Worker がキャッシュしたファイルが表示されるため、**何かを変えたら必ず `sw.js` の `VERSION` を上げてから push** します（上げないと利用者に届きません）。

- **辞書データ（`data/`）を変えたとき** — `data/meta.json` の `dataVersion` と `counts` を更新し、`sw.js` の `VERSION` を上げます。`tools/validate.html`（または `node tools/validate-cli.mjs`）でエラーが 0 件であることを確認してから push します。エントリファイルを増やしたときは `meta.json` の `entryFiles` にも追加します
- **アプリ本体（HTML・CSS・JS）を変えたとき** — `js/config.js` の `APP_VERSION` と `sw.js` の `VERSION` を上げます。ファイルを追加・削除したときは `sw.js` の `SHELL` も直します（`node tools/check-sw.mjs` で漏れを確認できます）
